# Drone-Based Ocean Dye Plume Tracking
### IIT Madras Internship Project

A Python pipeline to detect and track a fluorescent green dye plume released in the ocean using drone aerial imagery. The system estimates the surface current speed and direction by geo-referencing the dye centroid across 500+ images using the drone's GPS and attitude telemetry.

---

## Project Overview

A drone hovers above the ocean while a fluorescent green dye is released into the water. The drone captures images continuously. This pipeline:
1. Matches each image to its telemetry (GPS position, altitude, roll, pitch, yaw)
2. Detects the dye plume using green-excess colour segmentation
3. Projects the dye centroid from pixel coordinates to real-world GPS coordinates
4. Tracks the centroid across all frames to estimate drift speed and direction
5. Generates a clean visualization video of the dye evolving over time

## How to Run

### Step 1 — Match Images to Telemetry
**Script:** `match_images_to_log.py`

Reads EXIF GPS data from each image and matches it to the nearest entry in the flight log by lat/lon proximity. Outputs `matched_image_log_500.csv`.

Before running, update the image folder path:
```python
files = sorted(glob.glob(r"YOUR_PATH\QUAD500\*.JPG"))
```

```bash
python match_images_to_log.py
```

**Output:** `matched_image_log_500.csv` — one row per image with GPS, altitude, roll, pitch, yaw.

---

### Step 2 — Geo-Reference Dye & Compute Velocity
**Script:** `geo_reference_500.py`

For each image:
- Crops a fixed Region of Interest (ROI) where the dye appears
- Detects the dye using green-excess segmentation
- Projects the dye centroid pixel to real-world lat/lon using camera geometry and drone attitude
- Computes frame-to-frame and bulk velocity of the dye drift

Before running, update the image folder path:
```python
IMAGE_FOLDER = r"YOUR_PATH\QUAD500"
```

```bash
python geo_reference_500.py
```

**Outputs:**
- `georef_centroids_500.csv` — per-frame dye centroid, lat/lon, velocity
- `plume_trajectory_500.png` — spatial trajectory and speed-over-time plots

---

### Step 3 — Dye Visualization Video
**Script:** `dye_visualization.py`

Generates a video showing only the isolated green dye on a clean dark background, evolving across all 501 frames. Background, boat, and other objects are removed — only dye pixels are shown.

Before running, update the image folder path:
```python
IMAGE_FOLDER = r"YOUR_PATH\QUAD500"
```

```bash
python dye_visualization.py
```

**Output:** `dye_evolution.mp4`

## Technical Details

### Region of Interest (ROI)
A fixed 530×430 pixel crop at position (1750, 2620) is applied to every image. This minimises the effect of drone drift between frames by restricting analysis to a stable window where the dye consistently appears.

### Dye Segmentation
Green-excess segmentation:
```
green_excess = G - (R + B) / 2
```
Pixels exceeding a threshold of 90 are classified as dye. Morphological opening and closing operations clean up noise and fill gaps.

### Geo-Projection
The dye centroid pixel is projected to ground coordinates through three stages:
1. **Pixel → Camera ray** using focal length derived from the camera's 94.4° horizontal FOV
2. **Camera → NED world frame** using roll, pitch, yaw rotation matrices (ArduPilot convention)
3. **Ray → Ground intersection** assuming flat ground at the drone's recorded altitude

A sanity check rejects any projection landing more than 200m from the drone's GPS position.

### Velocity Estimation
- **Frame-to-frame velocity** — displacement between consecutive valid frames divided by time interval (minimum 0.5s gap enforced)
- **Bulk velocity** — total displacement from first to last valid frame divided by total time. This is the most reliable estimate as it averages out per-frame noise.

## Notes

- The `logfile2.mat` file must be present in the same directory as the scripts
- All three scripts must be run in order (Step 1 → Step 2 → Step 3)
- Steps 2 and 3 are independent of each other and can be run in any order after Step 1
- Processing 501 full-resolution images takes several minutes; a progress counter prints every 50 images
